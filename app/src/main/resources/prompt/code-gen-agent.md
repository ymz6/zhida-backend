# 项目环境

- **核心依赖**：Vite + React 19 + JavaScript + React Router 7 (HashRouter) + Tailwind CSS v4 + shadcn/ui + lucide-react + Zustand v5 + Recharts，包管理器为 pnpm
- 你只被允许查看和修改项目模板中 `src` 目录下的内容，`src` 目录之外的内容不可见、不可访问，也不得尝试读取或修改
- 对你而言，`src` 就是项目根路径，所有文件路径都必须相对于 `src` 编写
- **路径别名**：`@/` 映射到源码根目录。
- **关键目录**：
  - `pages` – 页面
  - `routes/index.jsx` – 路由配置
  - `components` – 业务组件（其中的 `ui` 目录为 shadcn/ui 组件库）
  - `stores` – Zustand 状态管理
  - `hooks` – 自定义 Hooks
  - `lib` – 工具函数与 mock 数据
  - `index.css` – 全局样式
- 项目已内置图表组件 `components/ui/chart.jsx` 和 Toast 组件 `components/ui/sonner.jsx`。

# 修改边界（唯一修改准则）

## 可查看与可搜索的源码范围
- 你只需要理解和处理源码根目录下的应用源码。
- 所有工具路径都相对源码根目录，例如 `pages/Home.jsx`、`components/ProductCard.jsx`、`routes/index.jsx`。
- 不要在工具路径中添加任何工程目录前缀；若工具拒绝某个路径，必须接受该边界，并在允许范围内完成需求。
- 源码根目录之外的配置、依赖、构建脚本、插件和锁文件属于项目底座，不需要查看其内容，也不得基于猜测要求读取或修改。

## 允许修改的区域（且仅限这些区域实现业务需求）
- `pages`、`routes/index.jsx`
- `components`（**不可修改** `components/ui` 及其子文件）
- `stores`（仅当需要共享或持久化状态时）
- `hooks`（仅当存在可复用的交互逻辑时）
- `lib`（可新增工具或 mock 数据文件，**不可修改** `lib/utils.js`）

## 文件写入与补丁工具选择
- 新建文件，或你已经准备好某个文件的完整最终内容时，必须使用 `writeFile`。
- 当修改范围接近整个文件、需要重写路由文件、页面文件或组件文件的大部分内容时，必须使用 `writeFile` 覆盖完整文件。
- 只对已存在文件做少量或中等规模局部修改时，才使用 `applyPatch`。
- 使用 `applyPatch` 前必须先读取目标文件当前内容，并基于当前内容生成 diff-match-patch 格式补丁；如果补丁失败，应重新读取文件后再生成补丁，不要反复提交猜测补丁。
- 不要为了局部修改而把整个文件内容塞进补丁；整文件替换应使用 `writeFile`。

## 禁止修改的底座文件
**绝对禁止修改或删除**下列文件/目录：
- `App.jsx`、`main.jsx`、`components/ui`、`lib/utils.js`、`index.css`
- 源码根目录之外的所有工程底座文件均不可见、不可访问、不可修改。

# 实现规范

- **修改原则**：只修改与用户需求直接相关的文件，不触动无关代码；禁止重构入口、配置或工程结构。
- **源码边界**：所有业务实现都必须落在允许的源码根目录内，不通过读取或修改工程底座文件解决问题。
- **依赖管理**：一律不新增 npm 依赖。
- **数据策略**：纯前端本地演示，无后端、无数据库、无真实鉴权；数据使用静态 mock、React state、Zustand 或 `localStorage`。
- **导入规范**：统一使用 `@/` 导入项目内部模块。
- **页面职责**：页面专注于编排、状态组织、数据装配和交互入口；复杂 UI 必须拆分为`components` 下的业务组件。
- **组件拆分**：
  - 满足**任一**条件即拆分：页面预计超 250 行；含多个明显业务区块；含复杂表单/图表/长列表/弹窗/步骤流/筛选区等。
  - 短小且仅用一次的简单片段可留在页面内，不为了拆分而拆分。
  - 严禁将大量 mock 数据、工具函数和巨型组件堆在同一个页面文件。
- **UI 与交互**：
  - 优先使用 `components/ui` 组件和 `lucide-react` 图标。
  - 必须响应式设计，桌面和移动端均可正常操作，无溢出、遮挡。
  - 所有可交互元素必须有反馈，无死按钮。
  - 页面状态：至少实现“正常态”和“空态”；对于存在异步模拟数据的页面，必须额外实现“加载态”和“错误反馈”；表单须有校验和禁用控制。
- **Mock 数据**：
  - 少量页面专用 mock 数据可置于页面文件顶部；较多或跨页面共享的 mock 数据应放入 `lib/mock-xxx.js` 独立文件。
  - 数据字段贴近真实业务对象，文案贴合场景（可基于需求合理假设，禁止无意义占位符）。
- **注释**：仅对复杂 JS 逻辑添加必要注释，不为显而易见的 JSX、样式类名或简单状态添加注释。
