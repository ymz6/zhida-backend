# React SPA 项目模板介绍

- **核心依赖**：Vite + React 19 + JavaScript + React Router 7 (HashRouter) + Tailwind CSS v4 + shadcn/ui + lucide-react + Zustand v5 + Recharts
- **路径别名**：`@/` 映射到源码根目录。
- **`src` 目录结构**：
  - `pages` ：业务页面目录
  - `routes/index.jsx` ：路由配置
  - `components`：业务组件目录
  - `stores` – Zustand 状态管理仓库目录
  - `hooks` – 自定义 Hooks 目录
  - `lib` – 工具函数与 mock 数据目录
  - `index.css` – 全局样式
- **备注**：项目已内置图表组件 `components/ui/chart.jsx` 和 Toast 组件 `components/ui/sonner.jsx`。

# 其他提示

## `writeFile` 与 `applyPatch` 工具选择指南

- 新建文件，或你已经准备好某个文件的完整最终内容时，必须使用 `writeFile`。
- 当修改范围接近整个文件、需要重写路由文件、页面文件或组件文件的大部分内容时，必须使用 `writeFile` 覆盖完整文件。
- 只对已存在文件做少量或中等规模局部修改时，才使用 `applyPatch`。
- `applyPatch` 接收三个参数：`relativeFilePath`、`oldString`、`newString`。
  1. 调用前必须先 `readFile` 拿到当前文件内容，`oldString` 必须与文件逐字一致（含缩进与换行）。
  2. `oldString` 必须能唯一定位；若片段较短或重复出现，请把上下相邻 2-3 行一并放入 `oldString`。
  3. 一次调用只改一处；如需在同一文件改多处，请分多次调用 `applyPatch`。
  4. 删除片段时 `newString` 传空字符串。
  5. 失败时按返回的错误提示调整：错误信息中会附带文件中最相似的片段，请对照修正后重试；不要反复猜测提交。
- 不要为了局部修改而把整个文件内容塞进 `oldString`；整文件替换应使用 `writeFile`。
